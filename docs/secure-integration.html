Secure Integration

⚠️ Security Notice

This guide covers the secure, domain-based integration approach for Birkly. This is the recommended approach for production websites.

Overview

Birkly provides a secure, domain-based authentication system that eliminates the security risks of public API keys. Instead of exposing API keys in your website's source code, the system validates requests based on the domain making the request.

How It Works

1. Domain Registration

Before a website can access Birkly content, its domain must be registered and licensed in the CMS admin panel.

2. Automatic Domain Validation

When a website makes a request to the secure API, Birkly automatically:

  • Extracts the domain from the request headers (Origin or Referer)
  • Validates the domain against registered licenses
  • Allows or denies access based on license status

3. Subdomain Support

Licenses automatically cover all subdomains. For example, if example.com is licensed, then www.example.com, blog.example.com, etc. are also authorized.

4. Multiple Domain Support

Each license can support up to 3 domains total (1 primary + 2 additional). This is perfect for websites that use multiple domains for the same site.

Implementation

Step 1: Register Your Domain

Contact Birkly support or use the admin panel to register your domain:

  1. Go to /admin/license-management.html in your Birkly admin
  2. Click "Add New License"
  3. Enter your primary domain (e.g., example.com)
  4. Optionally add up to 2 additional domains (e.g., www.example.com, blog.example.com)
  5. Select your license plan
  6. Provide your contact email

Step 2: Use the Secure Template

Replace the standard template with the secure version:

<!-- Replace this -->
<script src="https://your-birkly-domain.com/cms-template.js"></script>

<!-- With this -->
<script src="https://your-birkly-domain.com/cms-template-secure.js"></script>

Step 3: Your Website Code

Your website code remains exactly the same. The secure template automatically handles authentication:

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>My Website</title>
</head>
<body>
    <div class="container">
        <h1>Latest Posts</h1>
        <div data-cms-template="blog-list">
            {for each entry in 'blog' sort="date:desc" limit=3}
                <div class="post">
                    <h2><a href="/blog/{entry.slug}">{entry.title|escape}</a></h2>
                    <time>{entry.date|date:YYYY-MM-DD}</time>
                    <p>{entry.content|escape|limit:200}</p>
                </div>
            {/for}
        </div>
    </div>
    
    <script src="https://your-birkly-domain.com/cms-template-secure.js"></script>
</body>
</html>

Development Mode

The secure template automatically detects development environments and falls back to the public API for easier development. No domain registration is required for local development.

Supported Local Domains:

  • localhost, 127.0.0.1, ::1, 0.0.0.0
  • localhost:8000 (with any port)
  • *.local domains (e.g., mysite.local)
  • *.test domains (e.g., mysite.test)
  • *.dev domains (e.g., mysite.dev)
  • Development: Uses /api/public.php (no domain validation)
  • Production: Uses /api/secure_public.php (domain validation required)

Error Handling

If domain validation fails, the secure template shows a user-friendly error message:

License Error: Domain not licensed. Please contact support to register your domain for Birkly access.

API Key Alternative

For advanced use cases, you can also use API key authentication:

// Generate API key in admin panel
const apiKey = 'your-api-key-here';

fetch('https://your-birkly-domain.com/api/secure_public.php?action=list_entries&collection=blog', {
  headers: {
    'X-API-Key': apiKey
  }
})
.then(response => response.json())
.then(data => {
  // Handle response
});

Security Benefits

  • No exposed credentials: No API keys in source code
  • Domain validation: Only authorized domains can access content
  • Automatic subdomain coverage: One license covers all subdomains
  • Multiple domain support: Up to 3 domains per license
  • Rate limiting: Per-domain rate limiting prevents abuse
  • Audit logging: All access attempts are logged
  • License expiration: Automatic access control based on license status
  • Local development: No registration required for development

Form Submissions (Pushing Data)

The secure system also handles form submissions from your website to Birkly. This ensures that only authorized domains can submit data to your collections.

Setting Up Form Submissions

  1. Enable Public Submissions: In your collection configuration, set "allow_public_submit": true
  2. Configure Form Settings: Add optional settings like auto-publish and notifications
  3. Use Secure Form Functions: Use the provided JavaScript functions for form handling

Collection Configuration Example:

{
  "name": "Contact Form",
  "allow_public_submit": true,
  "auto_publish": false,
  "notify_on_submit": true,
  "notification_email": "admin@example.com",
  "rate_limit": 10,
  "rate_limit_window": 3600
}

JavaScript Usage:

// Handle a form with automatic validation
HaruSecureForm.handleForm('#contact-form', 'contact_form', {
  onSuccess: function(result) {
    console.log('Form submitted:', result);
  },
  onError: function(error) {
    console.error('Submission failed:', error);
  }
});

// Manual form submission
const formData = {
  name: 'John Doe',
  email: 'john@example.com',
  message: 'Hello world'
};

HaruSecureForm.submitForm('contact_form', formData)
  .then(result => console.log('Success:', result))
  .catch(error => console.error('Error:', error));

Security Features for Forms

  • Domain Validation: Only registered domains can submit forms
  • Rate Limiting: Per-domain rate limiting prevents spam
  • Schema Validation: Automatic validation against collection schema
  • Honeypot Protection: Built-in spam protection
  • Audit Logging: All submissions are logged with domain and IP
  • Collection-Level Control: Each collection can enable/disable public submissions

Migration from Public API

To migrate from the public API to the secure API:

  1. Register your domain in the Birkly admin panel
  2. Replace cms-template.js with cms-template-secure.js
  3. Test your website to ensure everything works
  4. Remove the old template reference

Troubleshooting

Common Issues

Domain not licensed error

Cause: Your domain isn't registered in Birkly

Solution: Contact support to register your domain

License expired error

Cause: Your license has expired

Solution: Renew your license in the admin panel

Rate limit exceeded

Cause: Too many requests from your domain

Solution: Upgrade to a higher plan or implement caching
