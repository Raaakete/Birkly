# P5.7 — Admin UI spacing & alignment audit

**Phase:** 5.7 · **Milestone:** M0 (T2)  
**Date:** 2026-07-04  
**Scope:** Sidebar, shared components (`forms`, `tabs`, `cards`, `header`), Settings page vs reference pages (Dashboard, Content)  
**Method:** Static review of markup + CSS; compare token usage against `variables.css` and polished pages  
**Fix target:** M4 global spacing pass (`P5.7-M4-T2`, `P5.7-M4-T3`); structural dedup in M3 (`P5.7-M3-T1`)

---

## Executive summary

The admin design system is **partially unified** — Dashboard and Content lean on shared layout (`page-header`, `main-actions-bar`, `.card`, `.form-group` + `.input`) and rem tokens. Settings **reimplements** tabs, forms, and cards in `settings.css` (~1,800 lines) with denser inputs, a separate tab bar, and heavy inline styles. The sidebar nav has **no reliable icon–text gap** because `mr-xs` is used in markup but **never defined** in CSS, and `.nav-links a` has no `gap`.

Highest-impact fixes for M4: (1) sidebar flex `gap`, (2) align Settings forms/cards to `components/forms.css` + `components/cards.css`, (3) migrate Settings tab bar to `components/tabs.css`, (4) remove double page padding on Settings.

---

## Reference comparison

| Pattern | Dashboard / Content (polished) | Settings (current) |
|--------|--------------------------------|--------------------|
| Page shell | `page-header` + content only; padding from `.main-content` (`--space-10`) | Same header **plus** `.settings-page { padding: --space-6 }` → extra inset |
| Primary actions | One `main-actions-bar` at page level (Content) | Per-tab `main-actions-bar` (General, Security, Storage, Activity) — 4+ save bars |
| Tabs | N/A on these pages | Custom `.tab-nav` / `.tab-btn` — not `.tabs` / `.tab` |
| Forms | `.form-group` + `.input`; padding `--space-3` / `--space-4` | Bare inputs; `.settings-page .form-group input { padding: --space-2 }` |
| Cards | `.card` with `--space-6` padding; icon+text via flex `gap` | `.card` + orphan `.card-header` / `.card-body` (no CSS); `.role-card` / `.user-card` use different padding |
| Section rhythm | `.dashboard-section` / `.stats-grid` use `--space-4`–`--space-8` | `.settings-section` uses `--space-10` / `--space-8` — looser vertical rhythm |

## 1. High-impact issues (P0 → fix in M4)

### P0-1 — Sidebar icon-to-text gap is broken (undefined utility + no flex gap)

**Symptom:** Nav icons sit flush against labels; plugin items often worse (no margin class at all).

**Root cause:**
- Markup uses `class="mr-xs"` but **`mr-xs` does not exist** in `utilities.css` (only `mr-1`…`mr-4`, `mr-s`, `mr-m`, etc.).
- `.nav-links a` is flex but has **no `gap`**.

**Files:** `admin/css/layout/sidebar.css` (`.nav-links a`), `admin/partials/sidebar.php` (lines 92–94, 133–136)

**M4 task:** `P5.7-M4-T2`

---

### P0-2 — Sidebar branding uses inline styles that bypass layout CSS

**Symptom:** Logo block spacing/sizing inconsistent with `.sidebar-header` rules; harder to align with nav row rhythm.

**Files:** `admin/partials/sidebar.php` (lines 83–86) vs `sidebar.css` `.sidebar-header` / `.sidebar-header .logo`

**M4 task:** `P5.7-M4-T2` (move to sidebar.css using tokens)

---

### P0-3 — Settings tab bar duplicates and overrides shared tabs component

**Symptom:** Settings tabs look and behave differently from the unified tab system; class-name collision on `.tab-content`.

| | Shared `components/tabs.css` | Settings `pages/settings.css` |
|--|------------------------------|-------------------------------|
| Container | `.tabs` — white bg, bottom border, `--space-6` margin | `.tab-nav` — `--bg-secondary` fill, no radius |
| Trigger | `.tab` — `padding: --space-3 --space-4`, underline active | `.tab-btn` — `padding: --space-4 --space-6`, filled active state |
| Content wrapper | `.tab-content { display: none }` | `.tab-content { display: block; margin-top: --space-6 }` |

**Files:** `admin/css/pages/settings.css` (lines 16–60), `admin/templates/settings.html` (lines 10–81)

**M4 task:** `P5.7-M4-T3` (after M3 migrates markup to `.tabs` / `.tab`)

---

### P0-4 — Settings form density overrides shared form system

**Symptom:** Settings inputs are visibly shorter/denser than Content modals and rest of admin; labels lighter weight.

Shared baseline: `forms.css` — `.form-group label { font-weight: 600 }`, inputs `padding: --space-3 --space-4`.

Settings override: `settings.css` lines 107–124 — label `font-weight: 500`, input `padding: --space-2`.

General/Security forms use bare `<input>` without `.input`; Storage/Activity use `.input` — **inconsistent within one page**.

**M4 task:** `P5.7-M4-T3`

---

### P0-5 — Double page padding on Settings

**Symptom:** Settings content sits noticeably more inset than Dashboard/Content.

- `.main-content { padding: var(--space-10) }` (`main-content.css`)
- `.settings-page { padding: var(--space-6) }` (`settings.css` lines 6–8)

Content/Dashboard: no extra wrapper padding — only `.main-content`.

**M4 task:** `P5.7-M4-T3` — drop or zero `.settings-page` horizontal padding.

---

### P0-6 — `card-header` / `card-body` markup with no component styles

**Symptom:** Update cards in Settings (and `updates.html`) render as a single padded `.card` blob; header/body don't align like Dashboard stat cards.

`components/cards.css` defines `.card` padding only — **no** `.card-header` / `.card-body`.

**Files:** `settings.html` (lines 174–207), `updates.html` (lines 18–51)

**M4 task:** `P5.7-M4-T3` — extend `cards.css` with header/body split or flatten markup.

---

### P0-7 — Per-tab save bars create uneven vertical rhythm

**Symptom:** Each tab repeats `main-actions-bar` with its own Save button; Content uses a single page-level bar.

**Files:** `settings.html` (General ~93, Security ~389, Storage ~573, Activity)

**M1 task:** `P5.7-M1-T2` (global Save) · **M4:** spacing pass after consolidation

---

### P0-8 — Settings vertical section rhythm heavier than Dashboard

**Symptom:** `.settings-section { margin-bottom: --space-10 }` vs `.dashboard-section { padding: --space-6 }` — Settings feels more stacked.

**Files:** `settings.css` lines 75–93 vs `dashboard.css` lines 112–125

**M4 task:** `P5.7-M4-T3`

## 4. CSS tokens to reuse (no new design language)

Use existing tokens from `admin/css/core/variables.css` — **do not introduce new spacing scale values**.

| Token | Value | Use for |
|-------|-------|---------|
| `--space-2` | 0.5rem | Tab icon–label gap (compact) |
| `--space-3` | 0.75rem | **Sidebar nav icon–text gap**; form row gaps |
| `--space-4` | 1rem | `main-actions-bar` gap; section title margin |
| `--space-6` | 1.5rem | Standard **card padding**; form-actions padding |
| `--space-8` | 2rem | Section bottom spacing (max) |
| `--space-10` | 2.5rem | **Main content area padding only** (single source) |

### Recommended sidebar nav recipe (M4-T2)

```css
.nav-links a {
  display: flex;
  align-items: center;
  gap: var(--space-3, 0.75rem);
}
.nav-links a svg,
.nav-links .nav-icon {
  width: 16px;
  height: 16px;
  flex-shrink: 0;
}
```
