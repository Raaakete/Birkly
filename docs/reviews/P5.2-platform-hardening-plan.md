# P5.2 — Platform hardening (roles, plugins, admin reliability)

**Status:** Approved (2026-06-29, Keven)  
**Follows:** Phase 5 + P5.1 complete on `main`  
**Trigger:** Live kekaba testing — AI slug failures, entry list broken, updates API 403, empty Users & Roles, plugin activation blocked

---

## Problem summary

| # | Symptom | Root cause (investigated) |
|---|---------|---------------------------|
| 1 | AI creates collections/entries with `_` in slugs → errors | Slug rule is `[a-z0-9-]` only; AI not instructed; create/update normalize differently in `api/ai_approvals.php` |
| 2 | Entry list pages broken / won't open | Hardcoded admin URLs in `entries.html`; missing collection meta normalization; possible safe-renderer edge cases on subdirectory installs |
| 3 | Update system fails silently or 403 | `api/updates.php` requires literal `role === 'admin'` while settings gate uses `manage_settings` |
| 4 | Users & Roles tab empty | No default seed in `settings/roles.json`; template reads `$settings['roles']` but data is `$roles`; user modals hardcode 3 roles |
| 5 | User plugin won't activate | **System bug:** `core/plugins/dependencies.php` uses empty `$haru_plugins` instead of `$birkly_plugins` → generic "Plugin dependencies not met" |
| 6 | Custom roles not usable everywhere | AI agents API hardcodes valid roles; pickers inconsistent; `birkly_ai_role_rank()` ignores custom roles |

---

## Goals

1. **Plugins work** — activate `user_management` and others; show real error messages
2. **Roles are real** — Admin/Editor/Author/Viewer seeded; permissions editable; one API feeds all pickers
3. **AI writes safely** — slugs always valid; collections normalized consistently
4. **Admin pages reliable** — entry list works on subdirectory installs (kekaba path)
5. **Updates work** — permission-aligned API; clear GitHub token errors
6. **User plugin path clear** — after activation fix, document site-user vs CMS-user separation

**Out of scope:** Kekaba production deploy (deferred); outbound BYOAI OAuth; plugin marketplace

---

## Locked decisions

| ID | Decision |
|----|----------|
| D1 | Slug policy: **lowercase letters, numbers, hyphens only** — normalize `_` → `-` at AI write boundary |
| D2 | Seed **default CMS roles** on install/migrate: admin, editor, author, viewer with permission matrix |
| D3 | **Single source** for role pickers: `GET /api/roles.php?action=list_roles` (or shared PHP helper) |
| D4 | Custom roles from `settings/roles.json` valid **everywhere** roles are picked (users, AI agents, service agents) |
| D5 | Plugin dependency check uses **`$birkly_plugins`**; surface `errors[]` in settings UI |
| D6 | Updates API uses **`manage_settings`** permission, not hardcoded role string |
| D7 | Admin templates use **`birkly_url()` / `{admin_url}`** — no hardcoded `/admin/index.php` paths |
| D8 | Kekaba embed sync **deferred** — document deploy checklist only |

## Technical approach

### AI slugs (P5.2-M2)

- Unify collection normalization in `api/ai_approvals.php` (create + update): `preg_replace('/[^a-z0-9-]+/', '-', ...)`
- Run entry slug through `birkly_resolve_entry_slug()` on AI create
- Optional: convert `_` → `-` in `core/entry_slug.php` before strip pass
- Update `docs/ai/birkly-context-pack.md` and AI chat prompt with slug rules
- Extend tool schema hints for `title` / optional `slug`

### Entry list (P5.2-M3)

- `getEntriesData()`: apply `birkly_normalize_collection_meta()`
- `admin/templates/entries.html`: replace hardcoded URLs with `{admin_url ...}` / `birkly_url()`
- Extract nested function in `getEntriesData()` if redeclare risk exists
- Add `entries` case to `tests/admin_routing_http_test.php`

### Updates (P5.2-M4)

- `api/updates.php`: `requireAuth('manage_settings')`
- `get_birkly_version()` in dependencies: use `BirklyVersion::getCurrentVersion()` / VERSION file
- Settings UI: show token/rate-limit hints from API errors

### Roles (P5.2-M1)

- `ensureDefaultRoles()` on first admin load or migration script
- Fix `getSettingsData()` → `$settings['roles'] = getRolesData()['roles']`
- Permissions editor UI (checkbox grid from canonical permission list)
- CMS user invite/edit modals: populate from `list_roles` API
- `birkly_ai_agents_valid_roles()` → read from roles.json + legacy fallback
- Match users to roles by **`role['id']`**, not display name

### Plugins (P5.2-M0)

- Replace `$haru_plugins` → `$birkly_plugins` in `core/plugins/dependencies.php`, `api/plugins.php`, audit related files
- `togglePlugin()` in settings: display `result.errors` when present

### User plugin (P5.2-M5)

- Smoke activate after M0
- Verify admin pages registered; site-user flows unchanged
- Cross-link CMS roles vs site-user roles in help copy
