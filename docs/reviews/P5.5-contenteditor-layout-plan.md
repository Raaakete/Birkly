# Phase 5.5 — ContentEditor layout power features (tables & grids)

**Status:** Proposed — awaiting human approval before lead execution  
**Repos:** Birkly (`fieldtypes/ContentEditor/` only) · Birkly-Docs (user-facing editor guide after stable)  
**Depends on:** ContentEditor init/toolbar reliability fixes on `main` (#67, dropdown/table hotfixes)

## Problem

ContentEditor basic formatting works again, but layout blocks are still modal-first and weak in visual editing:

| Gap | Today | Target |
|-----|-------|--------|
| Toolbar dropdowns | Broken when admin `dropdown.js` clobbered `.dropdown-menu` | Isolated CE menus (fixed in hotfix) |
| Table insert position | Lost selection after dialog → append to end | Insert at caret (fixed in hotfix) |
| Post-insert editing | Row/col add/remove via hover chrome only | Full visual layout studio |
| Grid | Initial modal only; limited cell styling | Same studio pattern as tables |
| Stored output | HTML + inline styles where needed | Pure HTML; editor-only `data-*` stripped on save |

**ContentEditor rule (unchanged):** All code in `fieldtypes/ContentEditor/`. Stored value = portable HTML.

---

## Vision

After a quick **setup modal** (rows/cols, preset, or template), tables and CSS grids become **first-class visual blocks** in the editor:

- Select block → floating **Layout panel** (not another modal for every tweak)
- **Drag handles** on row/column/grid tracks to resize
- **Gap**, **padding**, **background**, **border**, **radius** per cell/region
- **Grid-only:** `grid-column` / `grid-row` span, auto-flow, min/max track sizes, responsive stack breakpoint
- **Table-only:** header row/column toggle, column width drag, merge cells (stretch goal)
- All changes reflected live in Visual mode; HTML mode shows clean attributes/styles

Reference UX (not implementation): Notion databases layout, Webflow grid, Figma auto-layout — but output remains static HTML for Birkly templating.

## Technical notes

### HTML output contract

```html
<!-- Table -->
<table class="content-editor-table" style="width:100%">
  <colgroup><col style="width:33%"></colgroup>
  <tbody>
    <tr>
      <td style="background:#f3f4f6;border-radius:8px;padding:12px">...</td>
    </tr>
  </tbody>
</table>

<!-- Grid -->
<div class="content-editor-grid" style="display:grid;grid-template-columns:1fr 1fr;gap:16px">
  <div style="grid-column:span 2;background:#fff">...</div>
</div>
```

Editor-only (stripped on save): `data-ce-layout-id`, `data-ce-selected`, handle elements, resize overlays.

### Dependency order

```
M0 hotfix → M1 architecture → M2 table ∥ M3 grid (parallel after M1) → M4 cleanup → M5 docs
```

### Out of scope (Phase 5.5)

- Nested tables / grid-in-grid (Phase 6+)
- Formula cells / spreadsheet behavior
- Client-site CSS — preview still uses field `css_url`

---

## Success criteria

1. All toolbar dropdowns execute commands (align, heading, colors, media).
2. Tables/grids insert at caret, not document end.
3. User adjusts column width, gap, cell background, radius in Visual mode without modals.
4. Grid supports span + auto-flow presets.
5. Saved HTML renders on front-end without editor metadata.
6. Tests + docs + AI pack updated.
