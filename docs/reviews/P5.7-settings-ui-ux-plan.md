## Problem

Settings is the control center for every Birkly install, but today it is the **least polished** admin surface — and several issues reflect broader admin UX debt:

| Issue | Impact |
|-------|--------|
| **Monolithic template** | ~2,000 lines inline JS; dead `admin/js/settings.js`; duplicate logic vs standalone pages |
| **Broken feedback** | `showMessage` overridden to `alert()` — saves feel broken |
| **Non-functional storage** | DB backends advertised but not implemented; wrong keys; no API actions |
| **Save-only security toggles** | Lockout, password rules, CSRF flag persist but may not enforce — trust problem |
| **Wrong data binding** | General → media fields use mismatched keys/units (MB vs bytes, checkbox vs `'on'`) |
| **Subdirectory installs** | Hardcoded `/api/` paths in inline JS (Domains, etc.) |
| **Visual inconsistency** | ~104 inline `style=` attributes; custom tab chrome duplicates `components/tabs.css` |
| **Global spacing debt** | Sidebar nav icon-to-text gap, uneven form/card padding across admin |
| **No automated gate** | No `settings_*_test.php`; manual checklist only |

**User goal:** Cleaner, easier settings **without a new design language** — same Birkly tokens, shared components, every control verified end-to-end, plus admin-wide detail fixes.

---

## Vision

Settings becomes a **reference implementation** for Birkly admin UI:

- One tabbed layout using shared `tabs`, `forms`, `cards`, `modals`, `messages` components
- **Global Save** — one primary action, toast feedback, no per-tab confusion
- Every control maps **UI → stored value → runtime behavior** with a test
- Security toggles **enforce** protection; Storage DB backends **work**
- AI tab gets the **same UX standards** as every other tab
- AI/QA agents run a structured **settings verification matrix** (not ad-hoc clicking)
- Global admin audit fixes high-impact alignment/spacing issues using shared CSS

**Broader admin UI:** In scope via M0 audit + M4 shared CSS fixes (sidebar, forms, tabs). Full entries/content/media reskin is out of scope — follow Settings patterns later.

## Milestones

### P5.7-M0 — Audit, verification matrix & global UI inventory

**Goal:** Document every control and every high-impact UI defect before changing code.

**Deliverables:**

- `docs/reviews/P5.7-settings-audit.md`
- `docs/reviews/P5.7-settings-verification-matrix.md`
- `docs/reviews/P5.7-admin-ui-audit.md` — sidebar, topbar, forms, tabs, cards, lists

Each matrix row:

| Column | Purpose |
|--------|---------|
| Tab / section | Where in UI |
| Control label | What user sees |
| JSON / file key | Where value is stored |
| Runtime consumer | PHP/JS that reads it (or **NONE** = save-only bug) |
| Test type | `api` \| `http` \| `manual` \| `defer` |
| Expected behavior | One sentence |
| Current status | pass \| fail \| stub \| untested |

**AI/QA protocol:**

1. Agent walks matrix row-by-row — no skipping “boring” toggles  
2. For each control: set value → **global save** → reload → verify persistence → verify runtime effect  
3. Failed rows become M2–M4 tasks with severity  
4. UI audit items tagged by severity for M4  

**Acceptance:** Matrix covers 100% of interactive controls; UI audit complete; human approves scope before M1.

1. Every settings control is in the verification matrix with pass/fail status.  
2. Security toggles enforce; Storage DB backends work; no fake controls.  
3. **Global Save** + toast; subdirectory-safe API calls.  
4. Settings + **AI tab** use shared components; `settings.css` net smaller.  
5. Global admin UI audit completed; high-severity spacing/alignment fixed.  
6. Automated test suite guards regressions.  
7. AI/QA matrix executed and documented before closure.
