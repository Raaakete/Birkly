## Problem statement

The admin Settings page is a **~3,400-line monolith** with ~1,415 lines of inline JavaScript, ~280 lines of embedded audit-log JS, ~200 lines of inline CSS, and a separate **~1,800-line** `settings.css`. A dead `admin/js/settings.js` is never loaded.

Users experience:

- **Trust failures** — security toggles persist but are not enforced; storage tab advertises DB backends that do not exist.
- **Broken subdirectory installs** — 28+ hardcoded `/api/` fetch paths in settings inline JS.
- **Confusing save UX** — General/Security use `save_all`; Storage form has no handler; duplicate `showMessage` ends in `alert()`.
- **Display bugs** — General media fields use camelCase keys in template but snake_case in JSON (values appear blank after save).
- **AI tab debt** — functional but visually inconsistent with the rest of admin; ~1,050 lines of AI-specific CSS in `settings.css`.
- **Global admin polish gaps** — sidebar uses undefined `mr-xs` utility; settings reinvents tabs/forms parallel to `components/*`.

---

## Goals

1. **Honest, working settings** — every control either works or is removed/hidden.
2. **Single global Save** with toast feedback (D4).
3. **Real storage backends** — MySQL + PostgreSQL + flat-file default; test + migrate (D2).
4. **Runtime security enforcement** — lockout, password rules, session timeout, CSRF flag (D3).
5. **Maintainable codebase** — extracted JS, shrunk page CSS, shared components (D6).
6. **Admin-wide spacing pass** — sidebar, forms, cards, tab bars (D5).

## Architecture notes

### Settings data flow (target)

```
settings.html (markup only)
  → settings-page.js (tabs, save, fetch via Birkly.url)
  → api/settings.php (save_all, test_database, migrate_storage)
  → settings/*.json + core/settings/storage.json (unified storage config)
  → StorageFactory → FlatFileStorage | MySqlStorage | PostgresStorage
```

### Security enforcement (target)

| Setting | Read from | Enforce in |
|---------|-----------|------------|
| `session_timeout` | `security.json` | `api/auth.php`, session checks (existing) |
| `max_login_attempts` | `security.json` | `api/users.php` login |
| `lockout_time` | `security.json` | `api/users.php` login |
| `password_min_length` | `security.json` | `api/validate.php`, replace hardcoded 12 |
| `require_strong_password` | `security.json` | `validate_password_strength()` |
| `enable_csrf` | `security.json` | `validate_csrf_token()` gate |

### CSS strategy (D6)

- Move reusable patterns to `components/tabs.css`, `components/forms.css`, `components/messages.css`
- Target: `settings.css` ≤ ~600 lines (AI/MCP layout only where unavoidable)
- M4 applies audit fixes in `layout/sidebar.css`, `components/forms.css`, `layout/header.css`
