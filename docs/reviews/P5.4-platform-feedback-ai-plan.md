# P5.4 — Admin stability, platform feedback & AI knowledge

**Status:** Proposed (2026-06-16) — awaiting human approval  
**Follows:** P5.3 merged; live testing on `birkly.kekaba.com` still broken  
**Trigger:** Blank Content page, automation false “inactive”, wrong alpha-feedback model, AI context too shallow

---

## Problem summary

| # | Symptom | Root cause (investigated) |
|---|---------|---------------------------|
| 1 | Content page blank (sidebar only, no main area) | `getContentData()` nested `function countAllSubEntriesForCollection()` redeclares on second call → fatal; duplicate `</main>` in layout; `content.html` mixed raw PHP + parser directives |
| 2 | Entries still unreachable | Same fatal aborts page load; kekaba embed deploy lag; entry URL fixes in P5.3 not on production until sync |
| 3 | Automation “inactive” while in nav | `get_plugin_state()` read empty registry before `load_plugins()`; admin gate at `index.php:416` used registry-only check |
| 4 | Alpha Feedback wrong product model | Per-install triage page (`manage_settings`) — every Birkly admin sees it; feedback stored locally in `data/feedback/`; not routed to platform owner (Keven) |
| 5 | AI knows almost nothing about Birkly | `docs/ai/birkly-context-pack.md` is a short curated summary; templating/MCP/plugins depth missing; no sync when platform changes |
| 6 | Deploy gap | CMS fixes on `main` ≠ live until kekaba `Birkly-0.1/` sync + server deploy |

---

## Goals

1. **Admin pages render reliably** — no fatals, valid layout DOM, content/entries/automation work on subdirectory installs
2. **Platform-owned alpha feedback** — testers submit from any install; **only platform owner** triages; not exposed to customer site admins
3. **AI deep knowledge** — in-product chat and MCP agents have accurate, current Birkly knowledge (templating, admin, plugins, API, security)
4. **Deploy discipline** — embed sync + smoke checklist automated or documented per CMS release

**Out of scope:** Full design system rewrite; plugin marketplace; database backend

---

## Locked decisions (proposed)

| ID | Decision |
|----|----------|
| D1 | **Feedback is platform-owned** — floating submit on alpha installs; triage UI only on platform reference install or `birkly.com` admin; optional relay API |
| D2 | **Remove “Alpha Feedback” sidebar** from customer installs — keep floating submit only during closed alpha |
| D3 | **Feedback relay** — `POST` to configurable platform endpoint (`settings/platform.json` → `feedback_relay_url`) with install id + HMAC; fallback local queue for offline |
| D4 | **AI knowledge layers** — (L1) context pack in every prompt, (L2) MCP topic resources on demand, (L3) Birkly-Docs public corpus |
| D5 | **Same-PR rule** — any AI-facing behavior change updates context pack + MCP resource index in same PR |
| D6 | **CI gate** — `ai_context_pack_test.php` + `ai_knowledge_coverage_test.php` (required sections present) |
| D7 | **Nested helpers** — no function definitions inside `get*Data()`; file-level or dedicated helper file |
| D8 | **Embed sync** — run `scripts/sync-client-embed.sh` kekaba on every CMS release PR that touches admin/api |

## Technical approach

### P5.4-M0 — Admin render hotfix (immediate)

- `function_exists` guards for sub-entry counters (done in hotfix branch)
- Remove duplicate `</main>` — single close in `layout_footer.php`
- `content.html` → `{json content_bootstrap}` only
- `catch (Throwable)` in `admin/index.php`
- `get_plugin_state()` reads `settings/plugins.json` when registry empty (done)
- Empty state in `content-groups.js`
- Tests: double `getContentData()` call; content page HTTP smoke

### P5.4-M1 — Entries & automation verification

- Re-verify entry drill-down chain on subdirectory base path
- Automation: plugin page + API use unified `birkly_is_plugin_active()`
- Remove misleading “plugin deactivated” when nav shows active

### P5.4-M2 — Platform feedback model

- **Remove** sidebar “Alpha Feedback” from default installs
- **Keep** floating submit (alpha flag: `settings/platform.json` → `alpha_program: true`)
- **New** `api/feedback_relay.php` or outbound job → platform inbox (email, webhook, or `feedback.birkly.com` API)
- **Platform triage** — only on Birkly-Website / internal dashboard, not customer CMS
- Privacy: consent copy; no PII beyond submitter email + page context

### P5.4-M3 — AI knowledge system

- Expand `docs/ai/birkly-context-pack.md` — admin templating, fieldtypes, plugins, API surface, security boundaries
- **MCP topic resources** in `core/mcp_protocol.php`:
  - `birkly://docs/templating` → `docs/TEMPLATE_LANGUAGE_SPEC.md` excerpt
  - `birkly://docs/admin` → admin templating guide
  - `birkly://docs/plugins` → plugin architecture
  - `birkly://docs/ai` → BYOAI + MCP
- **AI chat tool** `read_birkly_docs` — fetch topic by slug (cached)
- Sync key sections to **Birkly-Docs** public site
- `tests/ai_knowledge_coverage_test.php` — pack mentions conditionals, MCP, slugs, plugins

### P5.4-M4 — Deploy & embed automation

- Document + script: post-merge sync kekaba + Birkly-Website embeds
- `docs/reviews/p5.4-deploy-checklist.md` — mandatory smoke on subdirectory install
- Optional: GitHub Action on Birkly `main` → open kekaba sync PR

### P5.4-M5 — Integration matrix & closure

- Manual matrix: content, entries, sub-entries, automation, feedback submit, AI templating Q&A
- Roadmap checkboxes; notify human once
