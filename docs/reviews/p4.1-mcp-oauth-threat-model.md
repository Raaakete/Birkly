# P4.1-M3 — MCP OAuth threat model

**Scope:** Inbound MCP OAuth for Claude remote connectors (RFC 9728 + RFC 8414 + PKCE + DCR).  
**Out of scope:** Outbound BYOAI OAuth, admin SSO, consumer “Sign in with Anthropic”.

## Assets

| Asset | Location | Sensitivity |
|-------|----------|-------------|
| MCP endpoint profiles (role, `require_approval`) | `settings/mcp_endpoints.json` | High — defines tool access |
| OAuth clients (DCR) | `settings/mcp_oauth.json` | High |
| Access / refresh tokens | `settings/mcp_oauth.json` | High — bearer = endpoint identity |
| API keys (legacy path) | `settings/mcp_endpoints.json` | High |
| Authorization codes (ephemeral) | `settings/mcp_oauth.json` | Medium — single-use, short TTL |

## Trust boundaries

```
Claude (claude.ai)  →  HTTPS  →  Birkly OAuth AS/RS  →  MCP tools (role + approval)
stdio bridge        →  API key header  →  mcp_server.php (unchanged)
```

- **Remote connector:** OAuth bearer maps 1:1 to an endpoint profile via `client_id` → `endpoint_id`.
- **stdio bridge:** API key only; recommended path; no OAuth surface.

## Threats and mitigations

| ID | Threat | Likelihood | Impact | Mitigation |
|----|--------|------------|--------|------------|
| T1 | Stolen bearer token reused | Medium | High | Short access-token TTL (1 h); refresh rotation; HTTPS only; revoke endpoint |
| T2 | Stolen API key (parallel path) | Medium | High | Existing rotation + lockout unchanged; `auth_mode` can disable API key |
| T3 | DCR client registers without admin intent | Medium | Medium | Token only issued if `client_id` maps to an `oauth`/`both` endpoint |
| T4 | Authorization code interception | Low | High | PKCE S256 required; codes single-use, 10 min TTL |
| T5 | Redirect URI hijacking | Medium | High | Strict `redirect_uri` match against registered URIs |
| T6 | CSRF on authorize | Low | Medium | `state` param required by clients; codes bound to `client_id` + PKCE |
| T7 | Token stored in plaintext on disk | Medium | Medium | Flat-file alpha; Storage file permissions |
| T8 | CORS abuse from non-Claude origins | Low | Low | CORS limited to `https://claude.ai` on OAuth endpoints only |
| T9 | Subdirectory path confusion | Medium | Medium | All discovery URLs via `birkly_url()` + absolute host helper |
| T10 | Privilege escalation via OAuth | Low | High | Bearer resolves existing endpoint profile only; role + `require_approval` unchanged |
| T11 | Rate-limit bypass via OAuth | Low | Medium | Same per-endpoint rate limit after bearer resolution |
| T12 | Rogue MCP client brute-forces tokens | Low | Medium | Invalid bearer returns 401; lockout applies to API key path |

## Auth modes per endpoint

| Mode | API key | Bearer | Use case |
|------|---------|--------|----------|
| `api_key` (default) | ✓ | ✗ | stdio bridge, curl |
| `oauth` | ✗ | ✓ | Remote connector only |
| `both` | ✓ | ✓ | Transition / mixed clients |

## Residual risks

1. **Flat-file token storage** — acceptable for self-hosted alpha.
2. **Auto-approve authorize** — admin creates endpoint + optional pre-registered client.
3. **No token revocation endpoint** — revoking endpoint invalidates future lookups; tokens expire within TTL.

## Security controls preserved (no regression)

- `require_approval` default **true**
- Role enforcement at tool execution (`core/ai_permissions.php`)
- API key rotation grace + lockout
- Audit log per endpoint
