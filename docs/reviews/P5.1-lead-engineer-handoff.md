## Execution prompt (copy to lead-engineer)

You are the lead-engineer for **Phase 5.1 — Hybrid AI agents (personal + service)** on the Birkly platform repo.

### Goal

Replace the ambiguous “many agents, same permissions confusion” model with **two agent types**:

1. **Personal agent** — one per site; each user connects with **their own** CMS role and permissions (dynamic).
2. **Service agent** — fixed role; visible only to admins and users/roles explicitly assigned by admin.

### Context (already on main)

- Per-agent connector URLs: `/mcp/agents/{agent_id}`
- OAuth: login + consent at `/oauth/authorize`
- Role rank ceiling stopgap in `core/ai_agents.php` — **replace** for personal agents with real permission resolution; keep as safety net for service agents only
- Admin UI bug fix: per-agent URLs display correctly on HTTPS (PR #51)

### Locked decisions (D1–D8)

| ID | Decision |
|----|----------|
| D1 | Agent `type`: `personal` \| `service` only |
| D2 | **One personal agent per site** — auto-provisioned, not user-creatable, not deletable (can disable) |
| D3 | Personal agent: tool permissions = **authorizing user’s** role + permissions from `getPermissionsForRole()` / `settings/roles.json` |
| D4 | Service agent: fixed role at create; visibility via `visible_to_roles[]` + `allowed_users[]` |
| D5 | **Admin** (`*` or `manage_settings`) sees all service agents; others see filtered list |
| D6 | OAuth authorize: deny if user cannot see agent; consent copy reflects type + effective access |
| D7 | Migrate existing agents → `type: service`, `visible_to_roles: ["admin"]` until admin re-assigns |
| D8 | Kekaba deferred; Birkly-Docs sync in P5.1-M5 |
