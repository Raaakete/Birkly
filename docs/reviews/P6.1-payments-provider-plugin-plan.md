**Status:** Approved — autonomous execution in **one sprint** (M0→M5)

**Depends on:** P5.7 complete on `main`  
**Handoff:** `docs/reviews/P6.1-lead-engineer-handoff.md`

## What this is

A **fully self-contained** plugin (`plugins/payments/`) that:

1. Connects site owners to **8 payment providers** (EU, US, Asia incl. China & Japan)
2. Registers **`payment_shelf`** on the Birkly service shelf for core + other plugins
3. Provides admin: **connections**, **activity log**, **provider selection** (fixed or auto)
4. Optionally exposes a **role-gated dashboard widget** (payment stats)
5. **Does nothing alone** — Cart, User, Events, etc. call the shelf

**Not in scope:** Products, checkout UX, memberships, cart, marketplace, consumer plugins.

---

## Design principles

| Principle | Rule |
|-----------|------|
| Self-contained | All code, data, admin, adapters in `plugins/payments/` |
| Shelf-only integration | Consumers use `get_plugin_service('payment_shelf')` — never Stripe/Mollie APIs directly |
| Unified activity log | Every API call + webhook → one ledger with `source_plugin` + `source_ref` |
| Security | Capability + role permissions; encrypted credentials; webhook signature only |
| Deactivate = off | Shelf empty; consumers check `isConfigured()` |

## Provider adapters (all 8 in this sprint)

| ID | Provider | Primary markets | Notes |
|----|----------|-----------------|-------|
| `stripe` | Stripe | US, EU, JP, SG, AU | Global default |
| `mollie` | Mollie | EU (DK, NL, DE, …) | iDEAL, SEPA, Bancontact, … |
| `paypal` | PayPal | Global | Wallet |
| `adyen` | Adyen | EU, US, APAC | Enterprise / multi-method |
| `square` | Square | US, CA, UK, AU, JP | US SMB |
| `razorpay` | Razorpay | India | South Asia |
| `komoju` | Komoju | **Japan** | Konbini, PayPay, JCB |
| `payssion` | Payssion | **China + Asia** | Alipay, WeChat Pay, UnionPay |

Each adapter implements `PaymentProviderAdapter` inside the plugin. Site owner enables only what they need.

**Implementation:** Thin REST clients inside plugin (or plugin-local vendor SDKs). **No** new root-level composer dependencies.

## Provider selection

### Site settings (Payments plugin)

| Setting | Values |
|---------|--------|
| `selection_mode` | `auto` \| `fixed` |
| `default_provider` | Provider ID when `fixed`, or auto fallback |
| `auto_rules` | Currency / country / method hints → provider priority |

### Consumer call

```php
$shelf = get_plugin_service('payment_shelf');
$shelf->createPayment([
  'provider_id' => null,           // null = auto; or 'mollie' to force
  'amount_cents'  => 2900,
  'currency'      => 'eur',
  'metadata'      => [
    'source_plugin' => 'shopping_cart',
    'source_ref'    => 'order_123',
  ],
  ...
]);
```

### Auto-resolve order

1. Explicit `provider_id` on request  
2. Consumer hint in metadata  
3. Currency (e.g. `jpy` → komoju)  
4. Country (e.g. `CN` → payssion)  
5. Payment method type (e.g. `ideal` → mollie)  
6. Site `default_provider`  
7. First enabled configured provider

## Shelf API (stable contract)

| Method | Purpose |
|--------|---------|
| `isConfigured()` | Any provider connected |
| `listProviders()` | All adapters + enabled/configured state |
| `listAvailableProviders($context)` | Filtered by context for checkout UI |
| `resolveProvider($context)` | Auto or explicit resolution |
| `createPayment($request)` | Start payment |
| `capturePayment($ref)` | Capture if supported |
| `refundPayment($ref, $amount?)` | Refund |
| `createSubscription($request)` | If adapter supports |
| `cancelSubscription($ref)` | If adapter supports |

Webhook processing is **internal** to Payments plugin; outcomes → activity log + `broadcast_event()`.

### Standard events

`payment_succeeded`, `payment_failed`, `payment_refunded`, `subscription_created`, `subscription_renewed`, `subscription_cancelled`, `subscription_past_due`

Register automation triggers for each (like automation docs pattern).

## Permissions

| Capability / permission | Access |
|-------------------------|--------|
| `manage_payments` | Connections, credentials, refunds, full admin |
| `view_payment_activity` | Full activity log |
| `view_payment_stats` | Dashboard widget aggregates only |
| `access_payment_shelf` | Granted to **consumer plugins** via plugin capability UI |

Admin pages and sensitive APIs require `manage_payments` or `view_payment_activity` as appropriate.

---

## Dashboard widget

| Setting | Default | Purpose |
|---------|---------|---------|
| `enable_dashboard_widget` | `false` | Opt-in (security) |
| `dashboard_widget_roles` | `["admin"]` | Role multiselect |

Widget shows: volume (today / 7d / 30d), success rate, by-provider breakdown, link to activity log.

**Platform addition (same sprint):** Extend plugin `settings_schema` + `api/dashboard.php?action=widgets` to filter widgets by role and `enable_dashboard_widget` — reusable pattern for all plugins.
