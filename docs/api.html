API

HaruCMS provides both a public read-only API for fetching content and a public write API for submitting forms to collections configured with Public API entry method.

Public Read API

The public read API is available at /api/public.php and allows fetching content without authentication (domain registration required).

Available Actions

  • list_collections - List all collections
  • list_entries - List entries in a collection
  • get_entry - Get a single entry by slug
  • get_site_settings - Get site settings (deprecated - use project settings instead)
  • get_collection_info - Get collection schema and API key (for Public API forms)

Example: List Entries

GET /api/public.php?action=list_entries&collection=blog

Response:
{
  "status": "ok",
  "data": {
    "entries": [
      {
        "id": "entry-123",
        "title": "My Blog Post",
        "slug": "my-blog-post",
        "content": "...",
        "created_at": "2025-01-15 10:00:00",
        "status": "published"
      }
    ]
  }
}

Example: Get Single Entry

GET /api/public.php?action=get_entry&collection=blog&slug=my-blog-post

Response:
{
  "status": "ok",
  "data": {
    "entry": {
      "id": "entry-123",
      "title": "My Blog Post",
      "slug": "my-blog-post",
      "content": "...",
      "created_at": "2025-01-15 10:00:00",
      "status": "published"
    }
  }
}

Public Write API (Form Submissions)

The public write API allows submitting entries to collections configured with Entry Method: Public API.

Endpoint

POST /api/public/collections.php?collection={slug}

Authentication

Requires an API key sent via header or query parameter:

  • Header: X-API-Key: your-api-key
  • Query: ?api_key=your-api-key

Example: Submit Contact Form

POST /api/public/collections.php?collection=contact
Headers:
  X-API-Key: your-api-key-here
  Content-Type: application/json

Body:
{
  "name": "John Doe",
  "email": "john@example.com",
  "message": "Hello, I have a question..."
}

Response:
{
  "status": "ok",
  "message": "Entry created successfully",
  "data": {
    "entry_id": "entry-123",
    "status": "draft" // or "published" if auto-publish is enabled
  }
}

Security Features

  • API Key Authentication: Each collection has a unique API key
  • Rate Limiting: Configurable submissions per hour (default: 10/hour)
  • Field Validation: Validates all submissions against collection schema
  • Honeypot: Hidden field to catch bots
  • CAPTCHA: Optional human verification (reCAPTCHA v3 or hCaptcha)
  • Auto-publish Control: Choose whether submissions are published immediately or saved as drafts

Admin API

Admin API endpoints require authentication and are used by the admin panel:

  • /api/admin_entries.php: Content management (list, get, create, update, delete entries)
  • /api/admin_collections.php: Collection management
  • /api/admin_media.php: Media upload, list, delete
  • /api/users.php: User management, login, logout
  • /api/settings.php: Settings management

Authentication

  • Admin API endpoints require session authentication and CSRF token
  • Public read endpoints require domain registration (Settings → Domains)
  • Public write endpoints require API key authentication

Request & Response Format

  • All requests use JSON or multipart/form-data (for uploads)
  • Responses are JSON objects with status, message, and data

Domain Registration

For security, your website's domain must be registered in HaruCMS:

  1. Go to Settings → Domains in the admin panel
  2. Click "Register Domain"
  3. Enter your domain name (e.g., "example.com")
  4. Set permissions (Read Only or Read & Write)
  5. Click "Register"

Note: For local development (localhost), domains are automatically allowed.

Example Requests

// List entries in a collection (Public API)
GET /api/public.php?action=list_entries&collection=blog

// Get a single entry (Public API)
GET /api/public.php?action=get_entry&collection=blog&slug=my-post

// Submit a form (Public Write API)
POST /api/public/collections.php?collection=contact
Headers:
  X-API-Key: your-api-key
  Content-Type: application/json
Body:
{
  "name": "John Doe",
  "email": "john@example.com",
  "message": "Hello!"
}

// List entries (Admin API - requires authentication)
POST /api/admin_entries.php?action=list&collection=blog
{
  "action": "list_entries",
  "collection": "blog"
}

// Public form submission
POST /api/public_submit.php
{
  "collection": "contact_form",
  "fields": { "name": "Alice", "email": "alice@example.com" }
}

Best Practices

  • Always validate and sanitize input
  • Use CSRF tokens for admin actions
  • Check API responses for errors
