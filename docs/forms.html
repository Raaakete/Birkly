Forms

Birkly allows you to create forms that submit directly to your collections. This is perfect for contact forms, newsletter signups, feedback forms, and more.

Entry Method

Each collection has an Entry Method that determines how entries can be created:

  • Admin Only (default) - Only entries created through the admin panel
  • Public API - Allows entries to be submitted via external websites using an API key

Setting Up a Public API Collection

  1. Go to Content → Collections in the admin panel
  2. Click on the collection you want to make public (or create a new one)
  3. Go to the Settings tab
  4. Change Entry Method from "Admin Only" to "Public API"
  5. An API key will be automatically generated
  6. Configure security settings (rate limit, auto-publish, CAPTCHA, etc.)
  7. Click Save Collection

Template-First Forms (Recommended)

Define your form HTML directly in your template using the {entry for} directive:

<div class="contact-form-wrapper">
{entry for 'contact'}
    <div class="form-group">
        <label for="name">Name <span class="required">*</span></label>
        <input type="text" name="{name}" id="name" required />
    </div>
    
    <div class="form-group">
        <label for="email">Email <span class="required">*</span></label>
        <input type="email" name="{email}" id="email" required />
    </div>
    
    <div class="form-group">
        <label for="message">Message <span class="required">*</span></label>
        <textarea name="{message}" id="message" rows="5" required></textarea>
    </div>
    
    <button type="submit">Send Message</button>
{endentry}
</div>

<script src="/birkly-client.js" 
        data-cms-url="https://your-cms-domain.com"></script>

How it works:

  • The {entry for 'contact'} directive wraps your form HTML
  • Field names use template variables like {name}, {email}, {message}
  • The client library automatically handles form submission, validation, and success/error messages

Auto-Generated Forms

Use the {public_form} directive to automatically generate a form based on your collection schema:

<div class="contact-form-wrapper">
    {public_form 'contact'}
</div>

<script src="/birkly-client.js" 
        data-cms-url="https://your-cms-domain.com"></script>

Field Name Mapping

When using {entry for}, field names in your HTML must match your collection's field slugs:

  • If your collection has a field with slug email, use name="{email}"
  • If your collection has a field with slug full_name, use name="{full_name}"
  • Field slugs are shown in the Templating tab of the collection editor

Legacy Form Syntax (Deprecated)

The old form syntax is still supported but not recommended:

{add entry to 'feedback'}
  {input name="name"}
  {textarea name="message"}
  {input name="email"}
  <button type="submit">Send Feedback</button>
{/add}

HaruForm JS Helper

  • Attach to any form for AJAX submission, CSRF, and error handling.
  • Hooks: onSuccess, onError.
<script>
new HaruForm('myFormId', {
  onSuccess: data => { /* show success */ },
  onError: err => { /* show error */ }
});
</script>

Anti-Spam & Security

  • Honeypot field (hidden input)
  • Simple math CAPTCHA (if enabled)
  • Akismet integration (if configured)
  • Rate limiting and CSRF protection are enforced automatically

File Uploads

  • Use {media name="attachment"} or <input type="file" ...> for file fields.
  • Files are validated and stored securely.

Email Notifications

  • Set notify_email in collection config to receive emails on new submissions.

Best Practices

  • Keep forms simple and user-friendly.
  • Use anti-spam features for public forms.
  • Validate and sanitize all input.
